# A long session alone

Robin, 2026-11-04 (the template): the Game Developer has a list he can work through on his own, asking the Art and
Sound Directors for what is needed as he goes.

1. Read `docs\autonomous.md` (its rules and its list), `docs\plan-chapter-N.md`, and the last morning report. Say in one
   line what you will take, in order, and start; do not wait for an answer.
2. For each item, in order: read `docs\state\` for the system (the skill `system-state`); build it; tests, the typecheck
   or the parse checks, the pane at the judging size with `?mute=1` when the screen changed; update `docs\state\`;
   commit with what and why; push. An item that fails twice gets a note in the list and the next is taken.
3. Ask the studios with the form in `docs\requests.md` the moment a piece is needed; put a stand-in in; copy a drop
   whole and commit it if it lands during the session.
4. Never alone: a design change, a felt number as final, a pick between concepts or songs, an install, a deploy, a cost,
   Robin's save or page. These go on the "waits for Robin" list.
5. Everything learnt goes where it belongs at once: a bug into a test, an idea into `docs\idea-bank.md`, a mistake into
   `docs\lessons.md`, a changed system into `docs\state\`.
6. End with the morning report (`docs\requests.md`): done (each with its commit), asked, checked, waits for Robin,
   found, next. Write its "waits for Robin" list into `docs\autonomous.md` under "The last report".
7. Robin's usage rule: at 90% of the weekly limit, switch to Opus and say so in the report.
